# План: буры (дрели + клей + движущиеся конструкции)

Цель: игрок сам строит бур как в Create. Склеивает дрели, валы и корпус, ставит конструкцию на рельсы (или на поршень/подшипник), подаёт вращение, и бур едет и копает.

Сверено с Horizon `c5c8a33` (`native-hooks.json`, `docs/native-mods.md`) 2026-11-06. Код Create (MIT, не assets) можно читать как образец: `Create/src/main/java/com/simibubi/create/content/`.

## Как это работает в Create (и почему так проще)

- Энергию потребляет **двигатель** конструкции: поршень, подшипник, ассемблер вагонетки (через вагонетку). Он сидит в обычной неподвижной сети вращения, и стресс берётся с неё.
- Дрели **внутри** движущейся конструкции вращение не получают. Они ломают блоки за счёт движения (`DrillMovementBehaviour`). То есть «передача энергии внутрь» для бура не нужна.
- Клей (`glue/`) задаёт, какие блоки едут вместе. Без клея держатся только «липкие» связи (дрель за свой вал и т.п.).

Делаем так же. Отдельная виртуальная сеть внутри конструкции остаётся опциональной фазой 7.

## Что даёт API и чего нет

| Нужно | Есть в API | Как закрываем |
|---|---|---|
| Блоки с логикой, тик, рендер с поворотом | `block_entity`, `block_entity_tick`, `block_entity_submit`, `rotate_about` | как сейчас |
| Ломать и ставить блоки | `native_set_block`, `native_edit_blocks` | есть |
| Дроп сломанного блока | хук `native_loot_drops` есть, **хелпера «сломать с дропом» нет** | `native_summon("minecraft:item", …)` с предметом блока. shortcut: без loot table (fortune, silk, особые дропы); апгрейд: попросить хелпер в Horizon |
| Движущиеся блоки | `native_summon` `block_display`, `native_move_entity`, `native_set_display` (клиентская интерполяция). Дисплеи сохраняются с миром (`persist.raw`) | конструкция = набор дисплеев |
| Коллизия конструкции с игроком | **нет** | не делаем: игрок проходит сквозь. Проверить позже, нельзя ли `interaction`/`shulker` как твёрдую подложку |
| Позиция ванильной вагонетки | **не нашёл хелпера** (`native_vehicle_moved` только с игроком внутри, `native_mobs` про мобов) | своя «тележка», которую мод сам ведёт по рельсам |
| Сохранение состояния конструкции | сущности сохраняются с чанками вместе с `persist.raw` (весь NBT) | снимок в `data` сущности `marker` (фаза 2). Сохраняется в тот же момент, что и блоки мира: своего файла, который может отстать от мира, нет |

## Новые блоки и предметы

| Id | Create-образец | Что делает |
|---|---|---|
| `mechanical_drill` | `kinetics/drill/` | `facing`. Стоит неподвижно: ломает блок перед собой от вращения. В конструкции: ломает блоки по ходу движения |
| `super_glue` (предмет) | `contraptions/glue/` | клик по двум углам = склеенная область. Хранится в `contraptions.json` и видна при взгляде с клеем в руке |
| `mechanical_piston`, `piston_extension_pole` | `contraptions/piston/` | двигает конструкцию по прямой, скорость = RPM |
| `mechanical_bearing` | `contraptions/bearing/` | вращает конструкцию (ветряная мельница, роторный бур) |
| `cart_assembler` | `contraptions/minecart/` | ставится на рельс, собирает конструкцию на «тележку» |
| `drill_cart` (сущность-дисплей, не блок) | `contraptions/minecart/` | своя тележка: едет по ванильным рельсам, мод сам ведёт её (см. фазу 5) |

Стресс (`stress.rs`, `VALUES`): дрель 4 su/RPM, поршень 4, подшипник 4 (значения Create сверить в `BlockStressValues`/конфиге Create).

## Фазы

Каждая фаза заканчивается проверкой в игре. Следующую не начинаем, пока не работает предыдущая.

### 1. Неподвижная дрель (~1–2 дня)
- `content/`: `mechanical_drill.json` (`facing`, форма), модель, рецепт, лут.
- `native/mixins/kinetics/drill.rs`: чистые правила. Сколько тиков на блок от RPM и твёрдости (формула из `DrillBlockEntity`), какие блоки нельзя (бедрок, жидкость, воздух, блоки мода с block entity — уточнить). Тесты в `Cargo.toml` как у остальных модулей.
- `drill_tick.rs`: прогресс копания в block entity, по готовности `native_set_block(air)` и дроп. Трещины ломания: проверить, есть ли хелпер; нет — без трещин.
- `drill_submit.rs`: голова крутится с RPM (как шестерни).
- Стресс: `impact("kinetics:mechanical_drill")`.
- Готово, когда: дрель от творческого мотора ломает камень перед собой, быстрее на высоких RPM, перегруз её останавливает, гогглы показывают стресс.

### 2. Ядро конструкций (~1 неделя): самая рискованная часть
`contraption.rs` (чистые правила, с тестами) + `contraption_*.rs` (хуки):
- **Сборка.** От «якоря» (поршень, подшипник, ассемблер) flood-fill по склеенным областям и «липким» связям. Лимит блоков (как в Create, 2048; для слабого ПК начать с 256). Запрещённые блоки: бедрок, жидкости, ванильные блоки с block entity (сундуки: позже).
- **Снимок.** Каждый блок: смещение от якоря, `BlockStateId`, данные block entity мода (скорость не нужна: после разборки сеть решится заново).
- **В мир.** Блоки убираются `native_set_block(air)` (флаги без дропа и без обновлений соседей, чтобы не сыпались факелы/рельсы). Для каждого создаётся `block_display`. Дрели и валы на дисплеях крутятся через `native_set_display`.
- **Сохранение.** ~~`contraptions.json`~~ Сделано иначе: снимок (origin, offset, target, блоки) лежит в `data` маркера с тегом `kinetics.contraption`, маркер едет вместе с конструкцией. Мир сохраняет его вместе с чанками, то есть в тот же момент, что и убранные блоки. Дисплеи только картинка: после перезагрузки или возврата чанка у них новые id, поэтому чужие дисплеи с тегом `kinetics.contraption_piece` удаляются и делаются заново из маркера.
- **Разборка.** Блоки ставятся на итоговое место (округление позиции). Если место занято: блок выпадает предметом, как в Create. Дисплеи удаляются.
- **Защита от потери блоков.** Сборка, шаг и разборка происходят за один тик, автосохранение их не разрывает. Конструкция не заезжает в незагруженный чанк.
- Сделано: `contraption.rs` (+ тесты), `contraption_command.rs`, `contraption_commands.rs`, `contraption_tick.rs`, `contraption_load.rs`. Команда: `/kinetics_contraption <from> <to> <dx> <dy> <dz>` (оператор): склеивает коробку from..to, собирает от угла `from`, везёт на 1/16 блока за тик.
- Готово, когда: команда-отладка собирает 3×3 блока в дисплеи, двигает их на 5 блоков и разбирает. После выхода из мира в середине пути и повторного входа ничего не потеряно.

### 3. Дрель в конструкции (~2 дня)
- `MovementBehaviour`: каждый тик для дрели в конструкции блок перед её текущей позицией получает прогресс ломания. Скорость = скорость движения конструкции. Если блок не сломан, конструкция стоит (как в Create: бур упирается).
- Столкновение с миром: перед шагом проверить блоки, которые займёт конструкция. Твёрдый блок не перед дрелью = стоп (stall).
- Сделано: `contraption.rs` (`cells`, `way`, `drills_toward`, `drill_rpm` + тесты), в `contraption_tick.rs` перед шагом проверка пути и `c_drill`. «Твёрдый» = `BlockState.isSolid` (`legacy_solid`): трава и факелы не останавливают, дрель их ломает. Прогресс дрели хранится в куске маркера (`breaker`). Дрели на дисплеях пока не крутятся.
- Готово, когда: из отладочной команды конструкция с дрелью едет в скалу и прокапывает тоннель, а без дрели упирается и стоит.

### 4. Клей + механический поршень (~3–4 дня)
- `super_glue`: два клика = область. Отрисовка рамки, когда клей в руке (`block_highlight`/`draw_cube`). Снятие: ПКМ по области с клеем или гаечным ключом.
- `mechanical_piston` + штанги: длина хода = число штанг. Скорость из RPM (формула из `MechanicalPistonBlockEntity`). Направление = знак вращения. Стресс от сети.
- Сделано (собирается в CI, в игре не проверено): `glue_use.rs` (суперклей: два клика = бокс-маркер `kinetics.glue`, шифт+клик снимает; рамки нет, ответ в чате), `piston_tick.rs` (поршень просит сборку через `contraption::REQUESTS`; ход = число штанг `piston_extension_pole` СЗАДИ поршня; скорость `piston_speed`; флаг `Extended` в block entity), сборка вынесена в `contraption_tick.rs` (`c_assemble`), клей едет вместе с конструкцией. Без головы/штанг, растущих визуально.
- Готово, когда: игрок сам склеивает дрели перед поршнем, подаёт вращение, бур выдвигается и копает, при обратном вращении возвращается и разбирается.

### 5. Тележка на рельсах (~1 неделя)
- `cart_assembler` на рельсе. Красный сигнал собирает конструкцию над ним на «тележку» (как в Create), снятие сигнала на другом ассемблере разбирает её.
- Своя тележка, не ванильная вагонетка: мод сам ведёт якорь по рельсам (прямые, повороты, подъёмы: правила формы рельса из blockstate `shape`). Скорость: начальный толчок + золотые рельсы (`powered=true`) ускоряют, как у вагонетки. shortcut: без физики ванильной вагонетки; апгрейд: если в Horizon появится хелпер позиции вагонетки — цеплять к настоящей.
- Тяга от вращения внутри (как «furnace minecart» Create): опционально, в фазе 7.
- Сделано (собирается в CI, в игре не проверено): блок `cart_assembler` = рельс (шаблон `powered_rail`, в теге `rails`), `assembler_tick.rs`: сигнал включился, склеенное над ним собирается в конструкцию с `heading` в маркере. Дальше `c_cart` в `contraption_tick.rs` на каждом рельсе выбирает следующий (`cart_next`: прямые, повороты, подъёмы и спуски), `cart_speed`: золотой рельс с током разгоняет, без тока останавливает, остальные и подъёмы замедляют. Разбирается на ассемблере без сигнала, там где рельсы кончились, или когда скорость упала. Без поворота конструкции на кривых и без физики вагонетки.
- Готово, когда: бур на рельсах едет в гору и прокапывает тоннель, останавливается на ассемблере и разбирается.

### 6. Механический подшипник (~3–4 дня)
- Вращение конструкции вокруг оси: каждому дисплею `left_rotation` вокруг якоря. Дрели на вращающейся конструкции копают по окружности.
- Разборка только на углах, кратных 90°.
- Сделано (собирается в CI, в игре не проверено): `mechanical_bearing` (`bearing_tick.rs`): со скоростью берёт склеенное перед собой (`spin` в запросе), `c_spin` крутит дисплеи вокруг оси через якорь (`left_rotation` через `native_set_display`), 0.3° за тик на RPM. Без скорости доводит до ближайших 90° и ставит блоки повёрнутыми (`facing` и `axis` поворачиваются, остальные свойства и данные block entity нет).
- Готово, когда: роторный бур на подшипнике прокапывает круг.

### 7. Опционально, после всего остального
- Виртуальная сеть внутри конструкции (`runtime.rs` на графе из снимка): моторы и рукоятки внутри крутят свои валы, тележка едет от своего мотора.
- Ванильные блоки с содержимым (сундуки в конструкции, Create's mounted storage) и сбор дропа в них.
- Коллизия для игрока (если найдётся способ в API).

## Риски

- **Потеря блоков игрока** при краше или выгрузке чанка посреди движения. Главный риск, отсюда порядок «записал файл → потом трогаю мир» и отладочные проверки в фазе 2.
- **Производительность** на i5-4250U: каждый блок — отдельная сущность. Лимит блоков в конфиге, замер в фазе 2.
- **Чанки:** конструкция заезжает в незагруженный чанк. Останавливаться на границе загруженных чанков.
- **Мультиплеер:** всё на сервере, дисплеи синхронизируются сами. LAN проверить в конце фазы 2.
- Непроверенное: сохраняются ли дисплеи через перезапуск без расхождения id, какие флаги `native_set_block` не дают дропа, есть ли хелпер трещин ломания, что `native_world_dir` отдаёт папку текущего мира. Всё проверяется в фазах 1–2.

## Оценка

Фазы 1–4 (дрель, ядро, клей, поршень) ≈ 2–3 недели и уже дают «строю бур сам». Тележка и подшипник — ещё ≈ 2 недели. После фазы 4 надо обновить «Scope» в README (contraptions частично есть).
